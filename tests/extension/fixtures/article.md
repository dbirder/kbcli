把零散信息变成可以再次使用的知识，关键是让**收集、整理和回顾**形成一个简单的循环。

> 让工具承担重复的工作，把注意力留给理解与判断。

## 从一条记录开始

先写下你现在知道的内容，再补充来源与下一步。不要等到结构完美才开始记录。

1. **收集**：把原始材料放进 `inbox/`，保留出处。
2. **整理**：用自己的话提炼结论，关联已有笔记。
3. **应用**：在项目中验证，再更新适用范围。

### 今天的整理清单

- [x] 记录资料的来源和时间
- [ ] 把一个问题拆成具体行动
- [ ] 周末回顾本周的新增笔记

## 目录如何分工

| 目录 | 用来保存什么 | 何时整理 |
| :--- | :--- | :--- |
| `inbox/` | 尚未处理的想法与材料 | 每天收尾 |
| `notes/` | 可以复用的知识 | 理解形成之后 |
| `projects/` | 项目目标、决策和过程 | 项目推进时 |
| `tasks/` | 需要执行的行动 | 每次完成之后 |

## 一个可复用的记录模板

```markdown
## 我想解决什么问题
写出具体场景与约束。

## 我目前的理解
用自己的话写下结论，并保留依据。
```

阅读时可以对照[关联笔记](阅读器-关联笔记.md)，也可以查看 [Markdown 语法参考](https://commonmark.org/help/)。
