# KB 工作台 · Chrome 新标签页

0.2.1 以网站收藏为新标签页主内容：左侧分组导航、中央网站卡片、右侧知识库待办与状态，设置从右侧抽屉打开。采用 Manifest V3，无构建依赖、远程脚本、统计服务或内容脚本。

## 加载与连接

1. 打开 Chrome 的 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”。
2. 选择本目录（包含 manifest.json）。也可以解压构建的 chrome-kb-0.2.1.zip，选择其中 chrome-kb 文件夹。
3. 打开新标签页，点击“设置”中的“知识库连接”，或右侧“连接知识库”，填写 kbcli 服务地址及**用户令牌**。需要 kbcli 0.1.2+；NAS 的服务地址由部署者提供。
4. Chrome 请求访问 NAS 主机时允许该地址。用户令牌来自 NAS 的 kbcli/service.env 中 KBCLI_USER_TOKEN，agent 令牌不能用于此页面。

设置与缓存仅保存在 chrome.storage.local，不使用 Chrome 账号同步；令牌不返回给新标签页的数据快照，不写入知识库或安装包。Chrome 本地存储不是加密密码库。更换服务地址需要重新填写令牌；断开连接会清除凭据与缓存，并移除该连接的主机授权。

Chrome 的主机权限按主机匹配，不能限定到具体端口。插件只向设置中指定的服务地址和固定 API 路径发请求；不跟随重定向，不发送网页 cookie。[Chrome 主机权限说明](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)。

## 网站收藏与设置

- 点击“收藏网站”，填写名称、HTTP/HTTPS 网址并选择分组；不带协议的网址默认使用 HTTPS。
- 支持新建和重命名分组；分组与网站的箭头按钮调整顺序。搜索期间禁用网站排序，清空搜索后可调整。
- 卡片右下角“⋯”编辑网站、修改所属分组或删除收藏。删除分组会将网站移入默认分组，保留网站内容；默认分组可以重命名、不能删除。
- 网站可按名称、域名及完整网址搜索。图标由域名本地生成，不向第三方图标服务发送浏览记录。
- 设置抽屉支持“在新标签页打开网站”“显示知识库侧栏”和“紧凑网站卡片”。按 Escape 或关闭按钮收起。
- 收藏与分组独立保存在本机 chrome.storage.local，未连接 NAS、NAS 离线或断开连接均可使用；暂不读取 Chrome 原生书签，不通过 Gitee 或 Chrome 账号同步收藏。
- 可导出 JSON 备份并在另一设备导入；合并保留现有数据，按分组名称匹配，同组相同网址去重。导出不包含 NAS 地址、令牌、展示缓存或显示偏好。导入文件上限 16 MiB，最多 100 个分组、2000 个网站。
- 多标签页共享同一份收藏。收藏与 NAS 使用独立请求队列，后台分别串行处理，版本改变时拒绝旧表单覆盖、保留输入；核对后可再次保存。

## 知识库操作约定

- 在右侧查看待处理、进行中、已完成和全部待办（全部中包含已取消项）；可按标题和标签查找。
- 新增填写标题、可选日期与标签。修改支持标题、日期、标签及执行状态；清空日期会移除截止日期。
- 完成使用列表勾选按钮，单独发送用户完成请求，保留原有内容审核状态，无需再次人工审核。已完成任务可通过编辑重新打开。
- 修改携带显示版本的文件哈希，编辑表单同时绑定打开时的连接版本；其他标签页切换 NAS 或重新保存连接后会保留草稿并禁止向新连接提交。冲突时保留草稿、显示服务端最新摘要并阻止覆盖；用户可明确选择载入最新内容再编辑。
- 网络失败时保留有时间戳的展示缓存，禁用写入。写请求失败不会自动重放；若保存结果不确定，先刷新核对。
- 页面可见时每 30 秒刷新，也可手动刷新。自动同步暂停时仍允许保存到 NAS，并提示尚不会推送。
- 自动同步只展示状态，不提供绕过暂停或强推入口。具体冲突在 NAS 处理，人工恢复按部署文档执行。

## 状态接口

使用 `/api/tasks`、`/api/status`、`/api/autosync`。知识库 API 返回当前认证角色，连接时必须确认 human；同步状态接口是只读的，服务端通过 KBCLI_AUTOSYNC_STATE_DIR 配置库外调度状态目录。

未配置目录显示“同步状态尚未接入”，读取失败、未启动、重试、暂停和心跳过期分别展示，不当作正常运行。Git 跟踪分支对齐不代表此刻已再次访问远端，页面会显示最近成功同步时间。内容格式正常也不等于内容已人工批准。

## 构建和验证

在项目根目录运行：

```bash
python3 scripts/build_extension.py
node --test tests/extension/*.test.mjs
uv run pytest -q
```

构建生成 dist/chrome-kb 与 dist/chrome-kb-0.2.1.zip。已有输出不会覆盖，重新构建请使用新的输出父目录，例如 --output dist/rebuild/chrome-kb（归档文件按版本命名）。构建只包含白名单资源，不打包测试 mock、凭据、缓存或本机环境。

浏览器交互的独立测试环境：

```bash
uv run python tests/extension/serve_fixture.py --workspace /tmp/kbcli-ui-test --port 18767
```

访问 http://127.0.0.1:18767，使用同一地址及测试用户令牌 ui-test-user。这是本机隔离知识库，Chrome API 在测试页面中由 shim 模拟，不是实际扩展加载环境；请勿在此测试页填写正式令牌。正式扩展包不包含 shim。

当前工具环境不支持通过 CDP 加载未打包扩展，因此自动化已覆盖页面、客户端、后端及 NAS 只读连接，尚需在真实 Chrome 中按上述步骤加载并确认主机访问权限。若浏览器另外请求本地网络访问，请按其提示授予 NAS 访问，不要关闭浏览器安全检查。

## 依赖与部署边界

NAS 服务可以在库外独立 Python 环境运行 0.1.2，旧版 skill/远端 CLI 保持协议兼容。更新服务不要求把软件升级写成知识内容，也不自动升级电脑上的 skill。插件不启动 Git 调度器，现有 NAS 自动同步仍由独立服务负责。

完整设计与实测见项目 [Chrome 插件说明](../../docs/chrome-extension.md)。
