# 动效研究与完整设置设计

## 设计判断

沿用无侧栏首页、文件夹浏览与底部状态栏。动效负责回答“哪个界面进入、什么内容变化、操作是否结束”。不加入持续旋转、视差滚动、整屏闪光或文字缩放。

颜色沿用深夜蓝 #0d1420、面板 #141e2c、层级 #1c2a3b、线条 #2a3b50、冷蓝 #a5c6f4、文字 #e8eef7；系统中文无衬线字体。首页居中、设置内容左对齐。标志性轨道细线静态保留。可选择山雾、暮色，背景只是衬底。

改进重点是因操作产生的短促运动。继续沿用固定弹窗几何尺寸，避免退出期间改变 display/flex-direction。没有添加网站逐个飞入的长队列，以免频繁切换时等待。

## 官方资料与候选

| 候选 | 已核实能力 | 本次取舍 |
| --- | --- | --- |
| [Motion](https://motion.dev/docs/animate) | 原生 JavaScript animate、弹簧、独立 transform、动画控制 | 本次实际接入。适合原生 JS 弹窗和高频交互，无需迁移 React |
| [Anime.js](https://animejs.com/documentation/easings/spring/) | spring() 支持 bounce、perceived duration、物理参数 | 合适备选；与 Motion 功能重叠，这次不同时加载两个引擎 |
| [GSAP](https://gsap.com/docs/v3/GSAP/gsap.timeline()/) | timeline 编排、反向/暂停/嵌套序列 | 适合复杂展示编排；当前浏览器工作台交互优先，暂不引入 |

这是结合现有技术栈和产品场景的设计判断，不是库的性能排名。优秀组件库的默认动画也需要正确管理关闭、焦点和中断，不能单靠换缓动曲线解决生命周期问题。

实际使用 npm motion 14.6.0（同版本 framer-motion / motion-dom / motion-utils），MIT，许可原文随包保留。仅打包 animate、stagger 的可达代码，生成 vendor/motion-14.6.0.mjs（约 64 KiB，未 gzip）。未来正式接入应再次评估仅引入 mini + spring 的取舍。本原型不声称达到官方 mini 的体积。

依赖从 npm 安装到临时目录后用 esbuild ESM bundle，已本地化；运行预览不加载 CDN、不联网、不使用 eval/new Function。正式 MV3 插件也应本地打包。

## 验证边界

Ego 实际浏览器验证结果见 previews/qa-report.json。尺寸采样用来确认退出过程中不缩放、不重排，不能代表帧率基准或所有设备的主观流畅性。最终动效手感以用户打开交互预览体验为准。

连续 Escape 通过 dialog keydown 预先 preventDefault，再调用同一关闭协调器；原生 cancel 也走同一协调器。避免连续原生关闭请求提前移除 top layer，确保退出动画保留完整排版。
