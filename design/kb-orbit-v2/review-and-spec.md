# KB 工作台整体 UI 重构提案

设计方向：**轨迹**。简约、低噪声、克制的科幻感，首先是一款每天高频使用的个人入口。

本轮完成代码审查、独立高保真交互原型和多尺寸验证。**没有修改已安装插件、收藏、NAS 或备份结构。** 原型内的 91 个公开示例用于还原内容密度，不是实际收藏副本；维护任务、备份和打开网站均为明确标注的演示。

## 1. 现状判断：不是动画数量的问题

当前能力已经完整，但视觉与交互规则是随着功能逐步叠加的。解决方向是先统一空间与状态模型，再统一组件和动效；只把动画调慢或更换配色，不足以解决不连贯。

| 问题 | 代码证据 / 用户影响 | 重构建议 |
|---|---|---|
| 高频分组切换与低频任务混用弹窗 | navigation-ui.mjs 打开分组使用 folder-dialog；查看一个分组就要进入/退出遮罩层 | 分组在原收藏区域内切换，用面包屑返回；页面框架不移动 |
| 不同组件节奏直接冲突 | style.css:236 通用 dialog 为 220ms；610 分组强制关闭过渡；667 图标编辑也关闭过渡 | 高频导航 0–100ms，任务面板统一 160ms，明确用途而非按历史补丁区分 |
| 明暗表面不统一 | 主页是深青背景，文件夹和编辑面板使用固定浅绿背景 | 深、浅两套完整语义色；面板与主页同主题，遮罩仅压暗 |
| 层级连续切换 | 分组 → 编辑网站 → 关闭编辑网站再打开 capture iframe；设置 → 恢复确认又叠一层 dialog | 图标直接合入编辑面板；最多一个主任务面板，二次确认在面板内局部展开 |
| 布局和 DOM 重建掩盖真实状态 | navigation-ui.mjs render 清空根容器、重建 Sortable；多处异步 storage 更新会触发 load | 正式实现按稳定 ID 更新节点，保留输入、焦点、滚动和拖拽源；后台状态只更新对应文字 |
| 模糊和材质堆叠 | 搜索、预览、知识抽屉及 backdrop 分别使用多层 blur；后续又局部禁用 | 默认不做整页实时模糊，用不透明表面和层级明度建立空间 |
| 工具权重过高 | 全部网站、获取图标、检查网站、管理、分组、收藏并列 | 一级只保留视图、工具和添加；低频维护进入工具菜单 |
| 设置变成长表单 | 外观、显示、收藏、同步、备份、连接纵向堆叠 | 按“外观与动效 / 收藏与布局 / 备份与同步”分区，错误就近呈现 |
| 页面内容过度装饰 | 大时钟与较大分组间距占据垂直空间；收藏实际是主要任务 | 缩小时钟，压缩头部，提升收藏的可见数量与点击稳定性 |

以上“不一致”和重建行为已由代码确认。**没有采样正式插件的帧时间，因此模糊和 DOM 重建的实际耗时仍需实现阶段用 Performance 工具测量，不把推测当作性能测量结果。**

## 2. 设计方向与视觉语言

深空蓝灰、雾银文字、冰蓝选中态。科幻感来自静态轨迹细线、精确对齐和稳定反馈；不使用持续旋转、星空粒子、闪烁霓虹、大面积渐变或到处发光的描边。

- 主页、编辑、设置、工具、知识库共享同一套表面和颜色。
- 深色作为默认方向，浅色保持同等完整度，不是简单反相。
- 字体沿用系统中文与西文字体，离线可用；标题 22px、正文 14px、辅助 12px，时钟 44–54px。
- 间距用 4/8px；圆角 8px 控件、12px 卡片、18px 主面板，避免所有元素套相同的大圆角。
- 状态同时使用文字和颜色。待复核为低饱和暖色；不把 CORS、超时和登录限制渲染成危险红色。
- 原有壁纸个性化能力可保留为可选项，但要由统一遮罩确保对比度，默认使用安静的静态背景。

具体 token 和方向自检见 [设计计划](design-plan.md)。

## 3. 信息架构与日常习惯

**主页：** 固定顶栏、固定搜索区域、唯一收藏滚动区、轻量固定状态栏。保留分组文件夹总览；15 个分组可直接进入，不需要打开多层窗口。分组导航栏可折叠，小屏改为按需展开。

**分组内：** 内容区域显示当前分组与返回入口，左侧可直接切换其他分组。返回时正式版应保留总览原滚动位置；各分组保存各自滚动与搜索上下文。原型目前演示单区域切换，正式版仍须补齐滚动记忆。

**搜索：** 输入框全程不重建、不丢焦点，实时筛选所有收藏；Enter 明确执行网页搜索。`/`、`⌘K` 或 `Ctrl K` 聚焦。Escape 一次只关闭最上层交互，清空检索后回到原分组。

**编辑：** 名称、地址、分组、图标在一个面板内完成。网站图标、图片链接、文字图标为局部标签，不再切换 iframe 弹窗。保存回到原位置；实际图标继续按已有规则只在创建或手动操作时获取。

**拖拽：** 保留直接拖动；左侧分组也是投放目标。悬停约 600ms 展开目标，插入线表示位置，松手才保存，Escape 取消。正式实现必须保留拖拽源 DOM，不能在悬停展开时销毁 Sortable。原型未实现拖拽，不以演示代替功能验收。

**知识库：** 右侧按需面板，文章、待办、同步在面板内切换；阅读文章仍在同一个面板里，收藏背景和滚动位置不动。

**维护：** 检查、获取图标、备份收进工具菜单。长任务有进度和停止，关闭面板后后台继续；只改行状态，不让整个列表重新进场。待复核项继续禁止批量删除。

**恢复/删除：** 二次确认使用当前面板内的独立确认区域，明确展示范围和影响，取消返回当前状态。Escape 先关闭确认区域，不顺带关闭整个设置面板。正式数据保护、版本冲突校验和撤销机制全部沿用现有逻辑。

## 4. 统一动效规范

| 操作 | 时间与位移 | 规则 |
|---|---|---|
| 悬停、选中、按钮 | 80–100ms，颜色/边框 | 不放大卡片，不推动周围内容 |
| 分组切换 | 0–100ms，轻微 opacity | 框架不动；连续切换取消旧动效，最后一次操作生效 |
| 搜索筛选 | 即时 | 不对每个字符播放整块列表动画 |
| 菜单 | 120–160ms，最多 4–8px | 不延迟接受点击 |
| 居中任务面板 | 160ms，Y 8px | 相同进入/退出逻辑，不缩放整页 |
| 右侧知识库 | 160ms，X 12px | 方向固定，内容不重新排列 |
| 拖动 | 指针实时跟随 | 仅目标轮廓和插入线反馈；拖拽期间不重建源 |
| 减少动态效果 | 无位移 | 保留焦点、状态文字和必要即时反馈 |

只动画 transform/opacity；不动画宽、高、blur、整页阴影。原生 dialog/popover 用 display、overlay 离散过渡保持进出层级一致，不用固定 setTimeout 锁住关闭。适配最低 Chrome 120，其他浏览器的预览以可用交互优先，退出动画可以降级为即时关闭。

这与 [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion) 强调高频操作中的克制、可中断反馈，以及 [Fluent 2 Motion](https://fluent2.microsoft.design/motion/) 强调一致、快速的运动方向一致；具体数值是本产品的建议 token，不是引用系统默认值。

## 5. 实现策略：复用能力，重建 UI 层

不改 navigation、appearance、backup payload 和 NAS 协议，不重新抓取图标，不修改收藏 ID/分组关系/排序。

1. 提取语义色、间距、字体、圆角和 motion token，整理组件 CSS，停止在文件尾继续叠加同名选择器。
2. 拆分页面壳、分组导航、稳定网格、统一面板、编辑器、维护列表；将高频导航与模态任务分离。
3. 将捕获表单与图标编辑状态整理为同一个 UI 组件，继续使用现有 controller 及版本校验、草稿和保存生命周期。
4. 原有拖拽、同步、备份、恢复、受限请求保护逐项回归；上线前用当前真实备份只读副本做隔离恢复一致性验收。

最大风险在“分组导航 + 拖拽 + 焦点/滚动”以及“统一编辑器 + 草稿/保存”两条链路，不应把它当成一次全局换肤。

## 6. 本轮交付及验证边界

交互原型支持：总览/分组切换、检索、紧凑视图、折叠导航、深浅主题、一个面板内编辑图标、设置分区、恢复确认、知识库阅读层级、维护进度演示、减少动态效果。

已验证：连续快速切换最后一次生效；顶栏/搜索/页脚位置不变；检索保留同一输入节点与焦点；Enter 保存演示编辑且不改变排序；知识阅读/恢复确认最多一个主 dialog；系统减少动态效果时无位移和动画等待；390px 无横向溢出，编辑面板位于屏幕内；资源请求仅本机原型文件。

未模拟真实收藏跳转、真实网络检查、图片获取、NAS 写入、拖拽、多设备冲突和浏览器插件生命周期。原型中的相应动作均为明确演示，不能视为正式能力已接入。没有修改正在使用的插件。

## 7. 设计验收清单

- 分组切换保持页面框架、搜索焦点、图标和滚动稳定，无黑白闪屏。
- 快速连续操作不排队，不等动画完成再响应。
- 同一主题下全部表面一致；正文和辅助文字对比度目标至少 4.5:1，控件边界按可识别性验收。
- 不叠加主任务弹窗；每次 Escape 只退一层，关闭后焦点回到触发位置。
- 拖拽、保存、失败、离线和冲突均有准确可撤销反馈，不用单一颜色传达结果。
- 正式实现在常见窗口大小测帧时间，避免 UI 更新触发长任务；帧率目标须靠真实 trace 验证，而不是凭原型观感宣称。
