# 弹窗关闭与悬浮抽屉 0.3.1

日期：2026-10-18 至 2026-10-19。仅调整 Chrome 插件 UI，不变更 NAS、知识库规范或凭据存储方式。

## 行为

- 文件夹、网站编辑、分组编辑、待办、知识库和设置共六类 dialog 均可点击外部关闭，Escape 和关闭按钮继续可用。
- 知识库与设置统一使用原生模态悬浮层；抽屉只覆盖页面，不改变主页、时钟或收藏网格的宽度、位置和排布。窄屏抽屉保留边距，便于点击外部。
- 嵌套时只关闭最上层弹窗，保留下层抽屉或文件夹；关闭后焦点返回原入口。
- 保存待办、收藏或分组以及连接服务期间，沿用 cancel 防误关保护。关闭设置时先清空令牌输入。
- 点击内部控件或留白不会关闭；从输入框内拖动到外部不会当作外部点击。

Chrome 134+ 使用 closedby="any"。Chrome 120–133 的兼容层依据指针起点及点击坐标判断外部，发送可取消的 cancel 请求，复用关闭保护与敏感输入清理，而不直接绕过业务保护调用 close。

- `node --test tests/extension/*.test.mjs`：38 项通过，包括四项新增关闭行为测试。
- `.venv/bin/python -m pytest tests/test_extension_package.py -q`：1 项通过。
- 使用真实隔离 kbcli 接口、测试专用 Chrome API shim 和 ego-browser；可复用场景为 tests/extension/verify_dialogs.mjs。仅允许 127.0.0.1 地址和测试令牌。
- 浏览器分别验证原生 closedby 和强制启用兼容层，两种路径覆盖六类弹窗、嵌套关闭、令牌清理、保存/连接保护、内部拖动及桌面/390px 布局。
- 使用 DOM 几何断言，比较抽屉展开前后主页、时钟和分组的 x/y/width/height，确保没有挤压或位移。

浏览器测试仍为隔离页面与接口联调，不替代真实 Chrome 扩展加载和权限弹窗验收。
