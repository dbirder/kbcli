# 持久图标缓存验收（0.8.0）

日期：2026-10-20。开发、隔离验证及真实 Chrome 缓存验证完成。

## 行为

- 首次获取图片响应，解码验证后发布到浏览器 Cache Storage；新标签页直接读缓存，不访问图标来源。
- 成功与缺失结果都持久保存，不按时间自动更新。浏览器手动 Reload 重新检查可见来源；设置中的“更新网站图标”检查所有收藏来源，最多四个来源并发。
- 手动批量检查期间保留当前显示；刷新失败保留已保存的好图标。版本索引单次提交，候选先写入，较旧请求不能覆盖较新结果。
- 跨域响应保持 opaque，只由图片元素解码，支持不透明响应跨页持久读取，不尝试提取受限像素。
- 只接受当前扩展自己的图片路由与收藏已有来源，固定请求 Chrome favicon 或 /favicon.ico；omit credentials/no-referrer，无新增权限，无任意 URL 代理。
- 缓存采用独立 Cache Storage；虚拟 HTTPS key 仅作存储标识，不会请求该域名。图标不进入 navigation、NAS 备份、共享同步或 Git。
- 未使用索引及超时孤立候选可在后台清理，浏览器存储失败不阻断收藏。

## Ego 真实 service worker / Cache Storage 验证

本机 18787 opt-in fixture，数据均为合成，不连接正式 NAS。使用实际图片 fetch 事件与真实 Cache Storage，网站图标来源端点设置 no-store，用计数器确认没有 HTTP 缓存掩盖来源请求。

1. 首页首次加载：chrome 来源 1 次、site 0 次；Canvas 像素为蓝色 [32,128,224,255]，缓存存在。
2. 将图片来源设为故障，打开第二标签：仍为 chrome=1/site=0，蓝色图标可见，没有新增来源请求。
3. 第二标签手动 Reload：两种来源均尝试并失败，计数 chrome=2/site=1，旧蓝色图标仍可见。
4. 恢复来源并切换绿色图片，设置中点击“更新网站图标”：site=2，像素变成 [32,192,80,255]。
5. 新开第三标签：来源计数保持 chrome=2/site=2，直接显示绿色图片。
6. 将 site 来源改为 localhost（页面为 127.0.0.1），通过真实 no-cors 请求获得 opaque 响应。持久缓存中同时存在 basic/opaque 数据，图片可见。随后导航至另一个新页面，来源计数保持 chrome=2/site=3，opaque 图片仍从本地显示。
