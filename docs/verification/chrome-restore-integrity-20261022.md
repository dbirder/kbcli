## 范围与隔离

用户要求验证收藏、分组、图标可完整恢复，且不影响当前数据。正式 NAS 只读导出当前设备最新备份副本，存入本机 0700 私有临时目录；源文件 0600，不进入仓库或报告。未读取浏览器数据库，未在当前 Chrome 插件执行任何操作。

测试使用单独 Ego 任务空间、本机 127.0.0.1:18827 页面和独立知识库。API 是本机 kbcli 0.1.5，Chrome API 为已有 fixture shim；连接令牌全部为合成测试令牌，自动备份和多设备同步在测试页禁用。真实恢复按钮和确认流程使用测试页实际 UI，不连接正式 NAS 写接口。

## 完整性结果

真实备份副本：15 个分组、91 个收藏；图片图标 image=1、auto=63，共 64 个；文字图标 text=27，无缺失。

1. 真实副本导入隔离浏览器后，通过“立即备份”写入独立 API，再读取该快照，完整 payload 与源副本逐字段一致。
2. 仅在测试源中模拟全部数据丢失：只留一个空分组、0 个收藏，同时改变显示偏好和外观设置。
3. 点击恢复预览再取消，空测试数据不变。
4. 点击确认恢复：15 个分组、91 个收藏完整还原。分组 ID/名称/顺序、收藏 ID/标题/URL/所属组/顺序、偏好、外观及每个图标对象（包括 WebP 字节和 sourceURL）均深度比对一致。
5. 切换全部网站视图，91 张收藏卡片存在，64 个 WebP 图片均加载完成且 naturalWidth > 0；27 个文字图标内容与颜色一致。
6. 重新加载页面，payload 仍与源副本完全一致，图标来源请求计数为 0。
7. 点击“撤销恢复”，准确回到此前模拟的空测试数据；再次确认恢复同一备份，完整 payload 再次一致。
8. 测试设备 ID、测试 NAS 连接及令牌在恢复前后保持不变。
