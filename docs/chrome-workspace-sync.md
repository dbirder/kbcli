# 配置、收藏与分组的多设备自动同步

Chrome 0.6.0 配合 NAS kbcli 0.1.4，在同一知识库内共享一份配置和收藏。每台电脑安装同版本插件并连接同一个 NAS 服务，自动同步默认开启；服务地址、用户令牌、设备名称和开关仍按设备保留。

| 自动同步 | 每台设备独立 |
|---|---|
| 收藏网址、标题、分组归属、顺序 | NAS 地址、令牌、主机授权 |
| 分组名称、顺序 | 随机设备 ID、设备名称 |
| 背景图片、主题、遮罩、模糊、位置 | 该设备是否开启同步、独立自动备份开关 |
| 搜索引擎、时钟、新标签页打开、知识库入口、紧凑显示 | 本机缓存、待传标记与重试时间 |

## 使用与首次接入

1. NAS 升级到 0.1.4，浏览器重新加载 0.6.0 插件，保留原本机存储。
2. 每台设备连接同一个知识库服务，右上角可直接进入“多设备同步”设置。
3. 最先带有收藏或自定义设置的设备建立共享版本。全新空白设备等待或自动接收共享内容，不会先发布空白数据。
4. 已有收藏的另一台设备首次接入时，如果与共享内容不同，会显示冲突。先预览再选择，系统不会直接覆盖。
5. 浏览器运行期间约每 30 秒检查，共享数据未变时仅获取版本元数据；本机连续编辑约 30 秒后提交。浏览器可能延迟调度，关闭/睡眠时不持续同步，重新运行后继续补传。

“已与共享版本对齐”指最近一次确认的 NAS 共享版本。NAS 到 Gitee 的提交推送仍由原 kbcli-sync 处理，状态在知识库侧栏单独展示；Gitee 暂停不等于本机内容未保存在 NAS。

## 离线与并发

收藏和设置保留在原 chrome.storage.local，本机编辑无需网络。上次确认的共享版本、内容指纹、待传请求 ID、接收保护备份 ID、冲突和退避状态持久化，不重复存储壁纸和整份 payload。每次恢复执行都读取存储，支持 worker/浏览器重启。

网络失败从 30 秒起指数退避，最多 30 分钟；“立即同步”可提前重试。请求结果不确定时重用请求 ID，GET 可查询已接受请求，即使另一设备已继续提交，也能恢复正确的共同基线，避免误判冲突或重复发布。

所有发布带 `base_revision`。NAS 在知识库写锁内比较当前版本：

- 基线一致：保存保护备份和新的不可变共享版本。
- 基线不一致：先保存提交方完整保护备份，返回 409；共享版本不动。
- 插件发现冲突后持久暂停自动覆盖，本机仍可编辑；重启不解除冲突。
- 接收远端前先保存当前本机保护备份，再核对连接和本机 revision，防止上传期间的新编辑被覆盖。保护备份失败时不替换本机数据。

本版按整份配置/收藏判断冲突，采取保守策略，不自动逐条合并。两台设备即使修改不同网站，只要都基于旧共同版本且内容不同，也可能需要处理。

## 处理冲突

“查看并处理冲突”并排展示本机和共享的收藏数量、分组、部分网站及外观配置。

- **接收共享版本**：先保护当前本机内容，再将预览的共享数据应用到本机。
- **发布本机版本**：以预览的共享版本作为新的比较基线，明确发布本机数据；原共享版本仍保留。

预览后任何一边发生变化都要求重新检查，不进行强制覆盖。窗口关闭可稍后处理；也可以先在本机整理后重新预览、发布。共享历史出现分叉、缺失、循环或哈希异常时停止同步，需要在 NAS 检查。

## 与现有备份的关系

原“自动备份、查看历史、手动恢复、撤销恢复”保留。共享提交、冲突提交和接收前保护快照也进入原设备备份目录，壁纸仍按内容去重。

关闭独立自动备份不会关闭共享同步所需的保护副本。恢复某份备份属于本机修改，后续会参与共享同步；如果期间共享版本也变化，会再次进入冲突处理。

## 服务端文件与权限

```text
assets/app-backups/chrome-kb/
  shared/<revision-uuid>.json            追加式共享版本链
  devices/<device>/<backup-uuid>.json   原备份及保护快照
  wallpapers/<sha256>.json              去重背景
```

没有可被旧客户端覆盖的可变 latest.json。共享版本声明父版本与全内容 SHA-256，只接受单条连通版本链；父引用缺失或存在多个分支时拒绝猜测“最新”。进程缓存只保存按 inode/size/mtime/ctime 核对的已校验版本元数据，完整数据始终来自文件，重启可重建。

共享 JSON 经 `chrome_workspace` 类型接入原操作日志、原子创建与受控 Git 提交，不改变 Markdown 规范、不进入知识索引、不扩大 Git add 范围。无需新增容器、数据库或凭据。

| 接口（仅 human 用户令牌） | 用途 |
|---|---|
| `GET /api/workspace/chrome` | 当前完整共享版本，或空 |
| GET 的 `known_revision` 参数 | 版本相同时仅返回元数据，避免反复传壁纸 |
| GET 的 `request_id` 参数 | 确认历史请求是否已接受 |
| `POST /api/workspace/chrome` | `{device_id,device_name,request_id,base_revision,payload}` 幂等版本提交 |

沿用 4 MiB 请求上限、100 分组/2000 网站、字段白名单、UUID v4 和路径/符号链接保护；agent 不得读写共享配置。NAS 地址和令牌不会进入共享 payload。共享历史及保护快照暂不自动清理，Git 历史会继续占用空间。

## 自定义网站图标兼容性

Chrome 0.10.0 为单条收藏增加可选 icon 字段，存储文字图标或规范化 WebP。NAS 需升级至 kbcli 0.1.5 才能接收含该字段的共享版本与备份；旧收藏不受影响。各设备应使用同版插件，以免旧客户端在重新导出时丢弃其不认识的图标字段。该版本代码更新不代表 NAS 已部署升级。
